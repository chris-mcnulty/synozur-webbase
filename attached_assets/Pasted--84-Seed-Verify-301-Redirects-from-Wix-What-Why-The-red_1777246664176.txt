#84 - Seed & Verify 301 Redirects from Wix
What & Why
The redirect infrastructure (DB table, Express middleware, admin UI) is already in place. This task seeds three sources of redirect rules and verifies they all resolve correctly:

The exported Wix redirect CSV (96 active rules).
53 additional rules from sitemap analysis — old Wix routing patterns that don't exist in the new site.
7 Group 1 rules — old URLs for pages that were on the old site but are not being rebuilt; these get redirected to the nearest equivalent.
Done looks like
All 96 CSV rules are seeded and active.
All 53 sitemap-analysis rules are seeded and active.
All 7 Group 1 rules are seeded and active.
No duplicate source paths exist.
The Express redirect middleware returns HTTP 301 for a representative sample across all three groups (e.g. /contact-us → /contact, /items/2026-ai-report → /library/2026-ai-report, /strategy-solutions/company-os → /solutions/company-os, /event-details/espc25 → /events/espc25, /plans-and-pricing → /contact, /free-consultation → /contact).
The admin Redirects page lists all entries and toggling active/inactive persists correctly.
Out of scope
Redirect analytics or hit-count reporting.
XML sitemap (separate task).
Steps
Finalize seed script — Review and complete seedWixRedirects.ts so it parses the CSV, normalises each source path (lowercase, strip trailing slash), and upserts rows into wix_redirects with statusCode 301. Skip rows with a blank Old URL or New URL.
Seed sitemap-analysis redirects — Add a second pass that upserts the 53 rules from the sitemap-analysis table below.
Seed Group 1 redirects — Add a third pass that upserts the 7 Group 1 rules below.
Run all seeds — Execute against the development database and confirm total row count with no duplicates.
Spot-check middleware — Curl a sample of old paths from all three groups and confirm 301 responses with correct Location headers.
Verify admin UI — Confirm all entries appear in the Redirects admin page.
