The bug:

The website's posts table has two separate columns — body_html and body_markdown. The admin editor (TipTap) initializes from body_html. But the MCP create_draft_post tool only writes body_markdown — body_html is never set. So when you open the post in the admin, TipTap finds an empty body_html column and shows a blank editor. The content IS in the database as markdown, just in the wrong column for the editor to read.

The fix — in Synozur-Baseline artifacts/api-server/src/mcp/tools/post-write.ts:

Add marked to the api-server dependencies, then convert the markdown to HTML before writing:

Step 1 — add to artifacts/api-server/package.json dependencies:

"marked": "^15"

Step 2 — update post-write.ts:

import { marked } from "marked";

Then in both create_draft_post and update_draft_post, compute bodyHtml from the markdown before inserting/updating:

// create_draft_post — inside the handler:
const bodyHtml = bodyMarkdown ? String(await marked(bodyMarkdown)) : "";
await db.insert(postsTable).values({
  id,
  slug,
  title,
  bodyMarkdown,
  bodyHtml,   // ← add this
  ...
});

// update_draft_post — inside the updates block:
if (bodyMarkdown !== undefined) {
  updates.bodyMarkdown = bodyMarkdown;
  updates.bodyHtml = bodyMarkdown ? String(await marked(bodyMarkdown)) : "";  // ← add this
}

That's the only change needed. Once deployed, posts pushed from Orbit will open in the admin editor with their content visible and editable.
